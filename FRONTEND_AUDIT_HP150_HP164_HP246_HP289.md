## Section F — Integration Gaps and Regression Risks

1. **Live Attendance Verification Dependency (HP150):**
   - *Risk:* In `Rating/index.jsx`, submitting a rating requires an active `classId` that matches an attended session in DynamoDB `beta_attendance`. If a user navigates to `/rating?instructorId=...` directly without `classId` or URL query params, they must select from `instructorClasses`.
   - *Evidence:* Lines 46-52 of `Rating/index.jsx` populate `instructorClasses` from `Ctx.previousClasses`.
   - *Mitigation:* The UI cleanly falls back to a dropdown session selector if `classId` is missing from the URL, preventing blocked users.

2. **Backend Authoritative Points Synchronization (HP150):**
   - *Risk:* Earlier implementations awarded client-side points optimistically on every submit click, creating points inflation on edits or duplicate clicks.
   - *Evidence:* `ContextProvider.jsx` line 913 now checks `if (data?.isCreated)`. Only newly created ratings trigger points increments. Edits (`data?.isUpdated`) and duplicate submissions (`data?.isDuplicate`) do not increment points.
   - *Status:* Resolved and verified by `ratingSystem.test.js` Scenario 10, 11, and 12.

3. **Timezone Alignment for Schedules & Notices (HP164):**
   - *Risk:* Backend schedules and notices store dates in `Asia/Kolkata` time or numeric epochs. Differences in client browser local timezones could filter out today's upcoming classes prematurely.
   - *Evidence:* `parseClassDate` safely converts numeric epochs, seconds, ISO strings, and Date objects. `UpcomingSessions/index.jsx` uses `startOfToday` comparison rather than `Date.now() + 1hr`, keeping all of today's classes visible.
   - *Status:* Resolved and verified by `hp164_hp246.test.js`.

4. **Multi-Currency and Subscription Deduplication (HP289):**
   - *Risk:* In institutions with both Razorpay (INR) and Stripe/PayPal (USD), or where Razorpay creates both a `sub_...` subscription record and a `pay_...` transaction record, totals could be inflated or currencies mixed.
   - *Evidence:* `deduplicateSubscriptionPayments` suppresses `sub_...` container records when matching `pay_...` transaction records exist. `calculateRevenueStats` segregates INR, USD, and Offline buckets.
   - *Status:* Resolved and verified by `hp289_revenue.test.js`.
